# Цена ошибки AI-агента — живые демо семинара

Код живых демо семинара «Цена ошибки AI-агента: как измерить, снизить. И когда автоматизировать нельзя», показанного на XXII Russia Risk Conference 15.10.2026. Спикер: Максим Шаланкин, MWS Fintech.

Все демо работают на локальных моделях через [Ollama](https://ollama.com), без внешних зависимостей (только стандартная библиотека Python). Все данные синтетические.

## О чём семинар

Решение об автоматизации принимает формула, а не ощущение от процента ошибок:

**ожидаемая цена ошибок = объём × частота ошибок × ущерб ошибки × (1 − обнаружимость × доля проверки)**

Две оси — цена ошибки и стоимость проверки — дают четыре квадранта: автомат, копилот, человек и ловушка («низкая на вид цена ошибки, высокая стоимость проверки»). Демо показывают каждый тезис вживую, на одном сквозном примере.

## Дуга демо: одна ошибка, увиденная трижды

Демо 1, 4 и 5 получают **один и тот же вход**: синтетический договор поставки (`demos/shared/contract.md`) и вопрос о неустойке (`demos/shared/etalon.json`). В п. 4.1 договора неустойка начисляется за **рабочий** день просрочки; эталонный ответ — 52 800 ₽ (22 рабочих дня × 0,1% × 2 400 000 ₽).

| Демо | Цикл | Что происходит |
|---|---|---|
| `demo1_confident` | 1 | Агент уверенно отвечает 240 000 ₽ — ошибка проходит незамеченной |
| `demo2_harness` | 2 | Eval-харнесс: «95%» на дружелюбном датасете превращается в провал на честном |
| `demo3_calculator` | 3 | Офлайн-калькулятор матрицы: экономика автоматизации на ваших числах |
| `demo4_verifier` | 4 | Тот же вход, но включён второй контур (правила + LLM-судья) — ошибка поймана |
| `demo5_consensus` | 4 | Флот из четырёх моделей голосует — общую системную ошибку голосование только подтверждает: эталон не набирает ни одного голоса |

Демо 1, 4 и 5 построены на одном промпте (`build_agent_prompt` в `demos/shared/run_agent.py`): ловушку нельзя починить в одном месте и забыть в другом.

## Раздатка

`handout.md` — одностраничная раздатка семинара, читается без спикера:

- **матрица «автомат · копилот · человек»** с критериями попадания в квадрант и банковскими примерами, плюс три расчёта с семинара (агент с 10% ошибок окупается, агент с 1% — нет);
- **чек-лист из 14 вопросов** к вендору или внутренней команде внедрения: про замер, регрессию, поведение при ошибке, архитектуру и доказательства;
- **числовая интуиция**: двадцать шагов по 95% — это 36% успеха; 4 минуты ревью против 11 часов отладки; человек нужен примерно на 2% задач.

## Быстрый старт

Требования: macOS/Linux, Python 3.10+, установленная Ollama.

```bash
# Модель контуров демо 1, 2 и 4
ollama pull qwen3:4b-instruct-2507-q4_K_M

# Флот демо 5
ollama pull llama3.2:1b qwen3.5:9b gemma4:12b
```

Запуск любого демо — одной командой из его папки (скрипт прогревает модель и стартует демо):

```bash
cd demos/demo1_confident && ./run.sh
```

Демо 3 — статичная страница без модели: открыть `demos/demo3_calculator/index.html` в браузере.

Все LLM-вызовы идут с `temperature 0` и выключенным thinking: вход детерминирован, ответы воспроизводимы. Ответы стримятся в терминал по мере генерации.

## Эталонные транскрипты

В папке `fallback/` каждого демо лежит проверенный транскрипт реального прогона — те же вход, та же температура, те же ответы. Если нет ollama или моделей, по транскрипту видно, как выглядел прогон.

## Структура репозитория

```
handout.md             # раздатка: матрица, чек-лист из 14 вопросов, числовая интуиция
demos/
├── README.md            # порядок демо, подготовка к прогону, эталонные транскрипты
├── shared/              # общий вход: договор, эталон, клиент ollama
├── demo1_confident/     # «Уверенный ответ»
├── demo2_harness/       # «Харнесс в прямом эфире» + генератор датасетов
├── demo3_calculator/    # офлайн-калькулятор матрицы (HTML, без модели)
├── demo4_verifier/      # «Тот же отказ, но с верификатором»
└── demo5_consensus/     # «Пять агентов»: флот из четырёх моделей
```

В папке каждого демо: `demoN.py`, `run.sh`, `fallback/` с проверенным транскриптом и `README.md` — что показывает демо, как запустить, какой результат ожидать.
