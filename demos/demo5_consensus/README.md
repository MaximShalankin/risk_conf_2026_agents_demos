# Демо 5, «Пять агентов» (цикл 4, сразу после демо 4)

## Запуск (одна команда)

```
./run.sh
```

Требование: запущенный ollama (`ollama serve`) и четыре скачанные модели: `llama3.2:1b`, `qwen3:4b-instruct-2507-q4_K_M`, `qwen3.5:9b`, `gemma4:12b`. Всё локально, интернет не нужен. Прогон около 2 минут (генерация ~55 с + загрузка моделей) + пауза на Enter после четырёх ответов.

`run.sh` прогревает все четыре модели перед стартом. Если в память помещаются не все, ollama выгрузит лишние — прогон не сломается, но агенту добавится несколько секунд на загрузку. Модели можно прогреть заранее: `ollama run <модель> ""` для каждой из четырёх.

## Что происходит на экране

1. Тот же договор и тот же вопрос, что в демо 1 и демо 4. Четыре независимых агента (четыре разные локальные модели) отвечают последовательно, сырые ответы печатаются как есть — суммы читаются глазами из заголовков, автопарсинга нет.
2. Ожидаемая картина (проверенный замер 15.10, temp 0, стабильна на повторных прогонах):
   - агент 1 (llama3.2:1b) — числа нет вовсе, ссылается на п. 4.3;
   - агент 2 (qwen3:4b) — **240 000 ₽**: ошибка демо 1 воспроизводится;
   - агент 3 (qwen3.5:9b) — поправляет себя по ходу и сходится на **48 000 ₽** («20 рабочих дней»);
   - агент 4 (gemma4:12b) — **140 000 ₽** в заголовке, 48 000 ₽ в расчёте, 144 000 ₽ в примечании.
3. Скрипт ждёт Enter — пауза, чтобы глазами сравнить четыре ответа между собой и с эталоном.
4. Строка голосования и вердикт: эталон **52 800 ₽** — ни одного совпадения. Двое, сошедшиеся на 48 000 ₽, сошлись на неверном числе по одной причине — неверный рабочий календарь.

## Тезис

Арифметика консенсуса верна — у неё два условия: ошибки агентов должны быть независимы, и каждый агент обязан быть чаще прав, чем неправ. Здесь не выполнено ни одно: ошиблись все четыре и ошиблись одинаково. Пятикратное повторение общей системной ошибки голосованием не лечится — оно её подтверждает. Поэтому контроль строится на правилах и эталоне (демо 4), а не на голосовании. Когда условия выполнены, консенсус работает и даёт сотые доли процента — это инструмент с паспортом применимости.
